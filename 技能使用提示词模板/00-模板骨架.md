# 提示词模板骨架（新增模板请复制本文件并填写）

> 用途：新增场景模板时，复制本骨架并按「三段式」填写，避免手工复制既有模板导致的编号错位、残留与占位符漂移。
> 约定：
> 1. 文件名编号 `NN-场景名.md`（单 Agent）与 `NN-场景名-多Agent.md`（多 Agent），正文大标题序号必须与文件名一致；
> 2. 占位符统一语义（速查见 `README.md` 占位符总表），花括号内只放占位符名；
> 3. 「多 Agent 模式」说明块按下方模板写：除端到端（08）外一律「可选」——开头追加「用多 agent / 团队协作模式」即启用；
> 4. 涉及状态机时，Gate 确认后的推进目标是**下一**内部 phase（advance <gatePhase+1>），置位用 `set-fw-gate.cjs`，advance 不自动置位；
> 5. 规则正文一律引用 `references/*.md` 与 `.agents/*.md`，不在模板内内联复制规则。

## 多 Agent 模式（可选 / 端到端默认启用）

在提示词开头追加「用多 agent / 团队协作模式」即可启用（端到端 08 默认即多 agent，无需追加）：编排器 `workflow-orchestrator`（`.agents/workflow-orchestrator.md`）按阶段<N> spawn 专职 agent **`<agent>`**（`.agents/<agent>.md`）执行，人工 Gate 由编排器管理（用户确认后 `set-fw-gate.cjs` 置位再推进）；状态机脚本（`scripts/`）负责门控校验与阶段推进，规则正文仍来自 `<references/xxx.md>`。不追加则默认单 agent 顺序执行。完整协议见 `references/multi-agent-orchestration.md`。

## 与单 agent / 多 agent 对应模板的区别

- 规则正文完全一致；区别仅在执行主体（主 agent 顺序执行 / 编排器+专职 agent）与门控方式（状态机脚本强制）。
