# 提示词模板 06：端到端全流程（Figma / .md → 交付）

> 规则依据：`SKILL.md` 第二节 2.2 端到端 12 阶段工作流；各阶段分别调度 figma-design-constraint / prototype-to-openspec-prd / frontend-engineering-standards。
> 适用：从原型（Figma 或 .md）一次走完「还原 → PRD → 业务实现 → 验收交付」整条流水线。

---

## 模板 A：完整版

```text
请使用 frontend-workflow skill，按 SKILL.md 端到端 12 阶段工作流，把下面原型（Figma 或 .md）完整交付为含业务逻辑的前端代码。

【输入】
- 原型来源：{{figma_url or md_path}}        # 二者也可同时给，若同时给则以 .md 文本为权威，Figma 补视觉/交互
- 目标项目目录：{{project_dir}}            # 需已 openspec init
- 技术栈：{{tech_stack}}
- 起止阶段：{{start_end}}                   # 如“从②开始到⑫”；若已有静态页面可跳过②③，须先确认

【执行要求】按固定阶段顺序推进，每个生成阶段后跑“生成 → 检查(只读) → 确认 Gate”：
  ② 生成静态页 → ③ 检查 → ④ 人工验收[Gate]
  → ⑤ 生成 OpenSpec PRD → ⑥ 检查 → ⑦ 人工确认需求[Gate]
  → ⑧ 设计桥梁 → ⑨ 生成业务逻辑 → ⑩ 检查 → ⑪ 人工验收业务[Gate]
  → ⑫ 终验[Gate]

- 各阶段规则来源：②③ 用 figma-design-constraint.md；⑤⑥ 用 prototype-to-openspec-prd.md；⑧⑨⑩ 用 frontend-engineering-standards.md。
- 检查 Agent 只读不写，输出结构化偏差报告，单环节最多回流 3 次，超出转“人工介入”。
- ④⑦⑪⑫ 为人工 Gate，**必须等我确认**，绝不可自动跳过。
- 意图解读（SKILL 2.1）先输出意图清单确认范围 / 技术栈 / 起止阶段；不明确就停下问。

【硬约束】
- 严禁猜测后端接口、业务规则、字段含义；信息不足必须停下问。
- 仅记录原型中存在的需求 / 状态，不自行补充。
- 安全硬约束（第四章）全程生效，无论需求是否体现。
```

## 模板 B：精简版（一行触发）

```text
用 frontend-workflow skill 按端到端 12 阶段工作流，把 {{figma_url or md_path}} 交付成含业务的 {{tech_stack}} 代码，写到 {{project_dir}}。每阶段生成后检查、到 ④⑦⑪⑫ 人工 Gate 等我确认；安全硬约束全程生效，别猜接口和字段。
```

## 占位符说明

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{figma_url or md_path}}` | 原型来源（二选一或都给） | `https://www.figma.com/file/xxx` 或 `docs/prototype-order.md` |
| `{{project_dir}}` | 目标项目根目录 | `F:/Develop/www/userlive` |
| `{{tech_stack}}` | 技术栈 | `Vue2.6 + JS + ElementUI2 + Vuex3` |
| `{{start_end}}` | 起止阶段 | `从②到⑫` / `跳过②③，从⑤开始` |
