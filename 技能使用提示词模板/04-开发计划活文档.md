# 提示词模板 09：开发计划活文档（Figma / .md 原型转本地活文档）

> 规则依据：`references/fw-dev-spec.md`（3.7 独立分支，是 3.2 原型→OpenSpec PRD 的**可切换替代方案**）。
> 适用：把用户提供的 **Figma 原型** 或 **`.md` 格式原型** 统一转化为本地 `.md` 的「开发计划活文档」，落在 `fw_dev_spec/<需求名>-<日期>/`（原型放子目录根、活文档放 `specs/`）。产出供 ⑧⑨（工程规范）实现使用；**不写 OpenSpec 文件**。输入读取与需求分析交叉引用 `references/prototype-to-openspec-prd.md`（2.2/2.3/2.4/第十章）；进度标记复用 `references/tapd-plan-template.md` 的 `⬜/🔄/✅/⏭`。

---

## 模板 A：完整版

```text
请使用 frontend-workflow skill，按 references/fw-dev-spec.md（3.7 开发计划活文档，OpenSpec 的可切换替代方案）把下面原型转为本地「开发计划活文档」。

【输入】
- 原型来源：{{source_type}}                    # 取值：Figma 或 md（.md 原型）
- Figma 来源（仅 source_type=Figma 时填）：{{figma_source}}   # Figma MCP 节点 / 链接 / 截图路径；如无可填“无”
- .md 原型路径（仅 source_type=md 时填）：{{md_path}}         # 用户提供的 .md 原型文件绝对路径
- 需求名称：{{requirement_name}}              # 用于子目录命名，如“订单管理”
- 项目类型（可选）：{{project_type}}          # 如 Vue3 / React / 小程序，辅助模块①说明

【执行要求】
1. 输入读取与需求分析：先 Read references/prototype-to-openspec-prd.md（2.2/2.3/2.4/第十章）做输入源判定与结构化需求清单；严禁猜测，未知项以 ⚠️ 待确认 标记并停问。
2. Figma→.md 原型转换（仅 Figma）：读取内容后先转成 .md 原型草稿，【人工 Gate·原型审阅】展示给你确认无误后，再存入 fw_dev_spec/<需求名>-<日期>/原需求-原型.md；.md 原型则直接归档（可规整，须告知）。
3. 目录处理：目标根 ./fw_dev_spec/ 已存在则直接用；不存在则先询问我是否新建（不擅自建）。子目录默认 <需求名>-<YYYY-MM-DD>，或直接问我期望的命名；写入前确认路径。
4. 组织形式决策：按需求大小给出建议并【询问】我采用「单文档」（specs/开发计划.md）还是「多 spec 文档」（specs/<模块>.md 拆分）；我选定后再生成，不默认假设。
5. 生成活文档（specs/ 下，统一五模块）：
   - ① 当前项目说明（背景/技术栈/运行命令/本活文档范围与原型文档路径）
   - ② 需求功能模块设计：每条需求标注关联锚点，格式：> 来源：原需求-原型.md · 章节「## xxx」；便于开发遇疑快速定位
   - ③ 按步骤划分的开发计划（Plan）：可勾选任务 - [ ] Px.y，引用对应功能模块
   - ④ 整体进度记录：进度总览表，状态标记 ⬜/🔄/✅/⏭（复用 tapd-plan-template 约定），开发中实时更新、中断可恢复
   - ⑤ 变更日志：日期/变更内容/影响；待确认项以 ⚠️ 待确认 标记
6. 随行更新：开发过程实时维护 ④ 进度与 ⑤ 变更日志，确保活文档始终反映真实状态。

【硬约束】
- 与 OpenSpec 二选一：本分支不写、不读取 openspec/，不改其 specs/changes；产出替代 ⑤ PRD 供 ⑧⑨ 使用。
- 人工 Gate 不可跳过：原型审阅（Figma）、目录新建确认、组织形式（单/多文档）选择，均须我确认。
- 严禁猜测接口契约/业务规则/字段含义；信息不足停下问，标注 ⚠️ 待确认。
- 分层存放：原需求原型文档放子目录根，活文档放 specs/，不得混放。
```

## 模板 B：精简版（一行触发）

```text
用 frontend-workflow skill 按 references/fw-dev-spec.md（3.7）把 {{source_type}} 原型（{{figma_source | md_path}}）转为开发计划活文档，需求名 {{requirement_name}}。Figma 先读内容转 .md 原型给我审阅确认后再存；fw_dev_spec 不存在先问我是否新建，子目录默认 需求名-日期；先建议并问我用单文档还是多 spec 文档，再按五模块（项目说明/功能模块+原型锚点/分步Plan/进度/变更日志）生成到 specs/，进度用 ⬜🔄✅⏭ 实时更新。不写 OpenSpec。
```

## 占位符说明

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{source_type}}` | 原型来源类型（必填） | `Figma` 或 `md` |
| `{{figma_source}}` | Figma 来源（source_type=Figma 时填）：MCP 节点 / 链接 / 截图路径 | `figma:node-id=xxx` 或 `https://www.figma.com/...` |
| `{{md_path}}` | .md 原型文件路径（source_type=md 时填） | `f:/dev/docs/订单管理-原型.md` |
| `{{requirement_name}}` | 需求名称，用于子目录命名 | `订单管理` |
| `{{project_type}}` | 项目类型（可选，辅助模块①） | `Vue3` / `React` / `小程序` |
