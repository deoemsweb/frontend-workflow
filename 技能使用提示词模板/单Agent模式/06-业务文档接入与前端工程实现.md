# 提示词模板 06：业务文档接入与前端工程实现（业务逻辑绑定）

> 规则依据：`references/frontend-engineering-standards.md`（第〇章业务文档接入与前置编排、API 集成、状态管理、第四章安全硬约束、性能、注释）。
> 适用：在已生成的静态页面 / 业务文档（OpenSpec 或 fw-dev-spec 活文档）基础上实现业务逻辑、集成接口、状态管理。

---

## 模板 A：完整版

```text
请使用 frontend-workflow skill，按 frontend-engineering-standards.md 实现下面业务逻辑（基于已生成的静态页面 / 业务文档）。

【输入】
- 静态页面 / 组件（可选，缺省时进入 0.4 校验）：{{page_or_component_path}}
- 业务文档路径（可选，缺省时自动探测）：{{biz_doc_path}}   # OpenSpec tasks.md 或 fw_dev_spec specs/ 活文档
- 原型来源（无业务文档时用）：{{prototype_source}}        # Figma / md / 无
- 技术栈：{{tech_stack}}                  # 如 Vue2/JS/ElementUI + Vuex
- 输出目录：{{output_dir}}

【执行要求】
1. 前置编排（第〇章，先于设计桥梁）：
   - 自动审阅项目根目录（只读）：探测 openspec/、fw_dev_spec/、package.json 技术栈、src/views|pages 与路由，输出项目画像；
   - 推荐并询问我连接哪套业务文档（已有 OpenSpec / 已有 fw-dev-spec / 两者皆有二选一）；若都没有，按原型来源推荐走模板 02（Figma→OpenSpec）、03（.md→OpenSpec）或 04（→fw-dev-spec）先生成业务文档，完成后再回来；未经我确认不得继续；
   - 校验目标静态页面/路由是否已存在：缺页面且有 Figma 时，询问我是否先走模板 01 还原生成页面与路由；缺页面且无 Figma 时，询问我是否直接根据业务文档生成页面与路由。
2. 设计桥梁（SKILL ⑧）：先产出组件树 / 状态 / 数据流草案给我确认，再写代码。
3. 按业务文档分步实现（SKILL ⑨ 的执行节奏，按第〇章 0.2 已确认的来源二选一）：
   - **OpenSpec**：读取 `openspec/changes/<change-id>/tasks.md` 的 Phase + `- [ ]` 任务清单 → 逐任务实现 → 每条任务对照 `spec.md` 的 Requirement/Scenario（GIVEN/WHEN/THEN）验证 → 完成后勾选 `- [x]`；遇疑回查 Scenario，信息不足停下问，严禁猜测业务规则 / 接口契约；
   - **fw-dev-spec**：读取模块③「按步骤划分的开发计划（Plan）」→ 按 ⬜→🔄→✅ 状态规则同步更新模块④进度总览（开始→🔄、完毕→✅、跳过→⏭并备注）→ 逐任务实现（借模块②「关联锚点」回查 `原需求-原型.md` 对应章节）→ 中断后重进时先读进度总览，从首个 ⬜ 或 🔄 继续，不打断整体进度；
   - 分步只约束「执行节奏与进度标记」，工程规则（三态 / 安全 / 性能等）仍按下一步执行。
4. 按 frontend-engineering-standards.md 实现：
   - API 三态（loading / error / empty）+ 请求取消 / 防竞态（组件销毁时 abort）；
   - 状态管理按项目现有 module 模式（如 Vuex / Pinia / Zustand，以项目 store 目录为准）；
   - 安全硬约束（第四章，无论需求是否体现都必须遵守）：禁用 v-html（用项目认可的净化方案/指令）、用户输入转义、URL 协议校验（禁 javascript:/data:）、禁止硬编码 API Key / Token / 密码、禁止 console.log 敏感信息；
   - 性能：图片 loading="lazy" + 明确尺寸、路由 / 组件懒加载、搜索防抖 / 滚动节流、长列表(>100)考虑虚拟滚动；
   - 注释：工具函数 / Hook / Store action 写 JSDoc，复杂逻辑必注释，TODO/FIXME 带责任人 + 日期。
5. 技术栈适配（以项目实际为准；Vue2 项目可参看 frontend-workflow-usage.md 映射表）：按项目现有写法（如 Options API 或 <script setup>）；API 走项目统一封装层，新接口按业务模块归类且写完善出入参注释；复用已注册的自定义指令 / 工具，不重复实现。
6. 完成后「检查 Agent」跑工程硬约束 + 非功能质量，单环节最多回流 3 次；到达人工 Gate（⑪）暂停验收。

【硬约束】安全规则全程生效；信息不足停止询问，严禁猜测业务规则 / 接口契约；前置编排各 Gate 未经确认不得进入下一步。
```

## 模板 B：精简版（一行触发）

```text
用 frontend-workflow skill 按 frontend-engineering-standards.md 给 {{page_or_component_path}} 实现业务逻辑，写到 {{output_dir}}。先按第〇章自动审阅根目录、推荐并问我用哪套业务文档（没有就先走 02/03/04 生成）、缺页面问我走 01 还原还是按文档直生成；再出组件树/状态草案确认；然后按业务文档分步实现——OpenSpec 读 tasks.md 逐任务勾选、fw-dev-spec 读模块③分步 Plan 并按 ⬜→🔄→✅ 更新模块④进度总览（中断从首个 ⬜/🔄 续）；遵守第四章安全硬约束（禁用未净化的 v-html）、API 三态+防竞态、复用已有自定义指令；完成后过检查并等我验收。
```

## 占位符说明

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{page_or_component_path}}` | 待绑定业务的页面 / 组件路径（可选，缺省时进入 0.4 校验） | `src/views/order/list.vue` |
| `{{biz_doc_path}}` | 业务文档路径（可选，缺省时自动探测 openspec/ 与 fw_dev_spec/） | `openspec/changes/add-export/tasks.md` 或 `fw_dev_spec/订单管理-2026-07-21/specs/开发计划.md` |
| `{{prototype_source}}` | 原型来源（无业务文档时用于推荐前置模板） | `Figma` / `md` / `无` |
| `{{tech_stack}}` | 技术栈 | `Vue2.6 + JS + ElementUI2 + Vuex3` |
| `{{output_dir}}` | 输出目录 | `src/views/order/` |

## 多 Agent 模式（可选）

在提示词开头追加「用多 agent / 团队协作模式」即可启用：编排器 `workflow-orchestrator`（`.agents/workflow-orchestrator.md`）按阶段⑧⑨ spawn 专职 agent **`frontend-implementer`**（`.agents/frontend-implementer.md`）实现业务逻辑，第〇章前置编排（⑧a）、⑪ 业务验收 Gate 由编排器管理；状态机脚本（`scripts/`）负责门控校验与阶段推进，规则正文仍来自 `frontend-engineering-standards.md`。不追加则默认单 agent 顺序执行。完整协议见 `references/multi-agent-orchestration.md`。
