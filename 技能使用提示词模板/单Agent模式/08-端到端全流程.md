# 提示词模板 08：端到端全流程（Figma / .md → 交付）

> 规则依据：`SKILL.md` 第二节 2.2 端到端工作流；各阶段分别调度 figma-design-constraint / prototype-to-openspec-prd / fw-dev-spec / api-definition-generation / frontend-engineering-standards。
> 适用：从原型（Figma 或 .md）一次走完「还原 → 业务文档（OpenSpec PRD 或 fw-dev-spec 活文档）→ 接口定义 → 业务实现 → 验收交付」整条流水线。

---

## 模板 A：完整版

```text
请使用 frontend-workflow skill，按 SKILL.md 端到端工作流，把下面原型（Figma 或 .md）完整交付为含业务逻辑的前端代码。

【输入】
- 原型来源：{{figma_url or md_path}}        # 二者也可同时给，若同时给则以 .md 文本为权威，Figma 补视觉/交互
- 业务文档方案：{{biz_doc_mode}}             # OpenSpec（默认）/ fw-dev-spec 活文档 / 到 ⑤a 由我决定
- Swagger 接口文档：{{swagger_source}}       # 可选；提供则走 ⑦b 接口定义生成
- 目标项目目录：{{project_dir}}            # OpenSpec 方案需已 openspec init；fw-dev-spec 方案无需
- 技术栈：{{tech_stack}}
- 起止阶段：{{start_end}}                   # 如"从②开始到⑫"；若已有静态页面可跳过②③，须先确认

【执行要求】按固定阶段顺序推进，每个生成阶段后跑"生成 → 检查(只读) → 确认 Gate"：
  ② 生成静态页 → ③ 检查 → ④ 人工验收[Gate]
  → ⑤a 业务文档方案[Gate]：确认用 OpenSpec（走 02/03）还是 fw-dev-spec 活文档（走 04），未经我确认不得生成
  → ⑤ 生成业务文档（按 ⑤a 选定：OpenSpec PRD 或 fw-dev-spec 活文档）→ ⑥ 检查 → ⑦ 人工确认需求[Gate]
  → ⑦b 接口定义生成(Swagger→函数/类型, 仅提供 Swagger 时) → ⑦c 人工验收接口[Gate]
  → ⑧a 第〇章前置编排：自动探测根目录 → 确认业务文档来源 → 校验页面/路由是否就绪（缺页面则问我走 01 还原还是按业务文档直生成）[Gate]
  → ⑧ 设计桥梁 → ⑨ 生成业务逻辑 → ⑩ 检查 → ⑪ 人工验收业务[Gate]
  → ⑫ 终验[Gate]

- 各阶段规则来源：②③ 用 figma-design-constraint.md；⑤⑥ 按 ⑤a 选定用 prototype-to-openspec-prd.md（OpenSpec）或 fw-dev-spec.md（活文档）；⑦b 用 api-definition-generation.md（探测项目既有接口模式后生成）；⑧a⑧⑨⑩ 用 frontend-engineering-standards.md（第〇章 + 全文）。
- ⑧a 第〇章说明：端到端通常已从 ② 生成静态页，页面/路由多为已就绪；但若跳过 ②③（已有页面场景）或业务文档要求的页面缺失，则按第〇章 0.4 询问——有 Figma 问是否先走 01 还原、无 Figma 问是否按业务文档直生成，等我选定后再继续。
- 检查 Agent 只读不写，输出结构化偏差报告，单环节最多回流 3 次，超出转"人工介入"。
- ④⑤a⑦⑦c⑧a⑪⑫ 为人工 Gate，**必须等我确认**，绝不可自动跳过。
- 意图解读（SKILL 2.1）先输出意图清单确认范围 / 技术栈 / 起止阶段 / 业务文档方案倾向；不明确就停下问。

【硬约束】
- 严禁猜测后端接口、业务规则、字段含义；信息不足必须停下问。
- 仅记录原型中存在的需求 / 状态，不自行补充。
- 安全硬约束（第四章）全程生效，无论需求是否体现。
- ⑤a 业务文档方案、⑧a 业务文档来源确认未经我同意不得默认其一。
```

## 模板 B：精简版（一行触发）

```text
用 frontend-workflow skill 按端到端工作流，把 {{figma_url or md_path}} 交付成含业务的 {{tech_stack}} 代码，写到 {{project_dir}}。先在 ⑤a 问我用 OpenSpec 还是 fw-dev-spec 活文档；每阶段生成后检查；⑧ 前走第〇章确认业务文档来源与页面就绪（缺页面问我走 01 还原还是按文档直生成）；到 ④⑤a⑦⑦c⑧a⑪⑫ 人工 Gate 等我确认；若提供 Swagger 则在 ⑦ 后自动生成接口定义；安全硬约束全程生效，别猜接口和字段。
```

## 占位符说明

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{figma_url or md_path}}` | 原型来源（二选一或都给） | `https://www.figma.com/file/xxx` 或 `docs/prototype-order.md` |
| `{{biz_doc_mode}}` | 业务文档方案（可留空到 ⑤a 再定） | `OpenSpec` / `fw-dev-spec` / `到⑤a决定` |
| `{{swagger_source}}` | Swagger 接口文档（可选，提供则走接口定义生成） | `docs/open.json` 或留空 |
| `{{project_dir}}` | 目标项目根目录 | `F:/Develop/www/userlive` |
| `{{tech_stack}}` | 技术栈 | `Vue2.6 + JS + ElementUI2 + Vuex3` |
| `{{start_end}}` | 起止阶段 | `从②到⑫` / `跳过②③，从⑤开始` |

## 多 Agent 模式（端到端默认启用）

端到端全流程**默认即走多 agent 编排**：在提示词开头追加「用多 agent / 团队协作模式」（或让编排器在意图解读阶段确认启用）后，由 `workflow-orchestrator`（`.agents/workflow-orchestrator.md`）按 ②~⑫ 阶段表依次 spawn 专职 agent 执行——`figma-restorer`（②）→ `prd-analyst`（⑤a⑤）→ `api-contractor`（⑦b）→ `frontend-implementer`（⑧a⑧⑨），每个生成阶段后由 `qa-reviewer`（`.agents/qa-reviewer.md`，只读）跑偏差报告，④⑤a⑦⑦c⑧a⑪⑫ 人工 Gate 由编排器管理；状态机脚本（`scripts/`）负责门控校验与阶段推进。单 agent 顺序执行只是可切换的默认回退。完整协议见 `references/multi-agent-orchestration.md`。
