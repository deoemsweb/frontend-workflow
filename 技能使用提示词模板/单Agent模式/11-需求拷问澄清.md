# 提示词模板 11：需求拷问澄清（grilling 追问协议）

> 规则依据：`references/grilling.md`（3.10 全局追问协议）。
> 适用：**开工前置**——在进入任何生成类分支（01~10）之前，先用一轮 grilling 澄清需求与方案；也可单独用于对某个既定计划/方案做压力测试。本模板可先于 01 使用。

---

## 模板 A：完整版

```text
请使用 frontend-workflow skill 的全局追问协议（references/grilling.md），对下述任务做拷问式澄清。只澄清、不动手：frontier 清空并经我确认共识之前，不生成任何代码或文档。

【任务】
{{task_desc}}

【已知输入】
- 项目/目录：{{project_dir}}      # 可选；提供则先自查技术栈/目录/既有依赖等事实
- 原型/文档：{{prototype_source}} # 可选：Figma 链接或 .md 原型路径

【执行要求】
1. 事实自查：能用工具探明的（技术栈、目录结构、业务文档存在性、接口现状）先自己 Read/搜索，不拿可自查的事实消耗我的提问额度（grilling.md 第五章）。
2. 建模设计树：把待决事项按依赖关系分支（任务范围/输入物/目标产物/起止阶段/技术栈/业务文档方案/测试范围等）。
3. 按 Frontier 轮次逐轮提问：每轮只问前置已落定的问题，一次性提出，逐题编号（Q1、Q2…），每题必带「➡️ 推荐答案及理由」；每轮 ≤4 问。
4. 我的回答使决策落定后重算 frontier 进下一轮；同一决策点最多追问 2 轮，超限降级为「剩余假设清单」一次确认（grilling.md 第四章）。
5. 每轮结束后输出当前「已落定决策」小结；frontier 清空后输出完整共识清单（决策 + 假设 + 推荐的后续分支/模板编号），等我确认「共识达成」后才结束。
```

## 模板 B：精简版（一行触发）

```text
用 frontend-workflow 的 grilling 追问协议（grilling.md）拷问澄清这个需求：{{task_desc}}。事实先自查，frontier 轮次逐轮问我（每题带推荐答案，每轮≤4问），走完决策树给我共识清单，我确认前不动手。
```

## 占位符说明

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{task_desc}}` | 任务/需求描述（一段话或粘贴原型要点） | `给订单列表页加导出 Excel 功能，需要权限控制` |
| `{{project_dir}}` | 目标项目根目录（可选，提供则先事实自查） | `F:/Develop/www/userlive` |
| `{{prototype_source}}` | 原型/文档来源（可选） | `https://www.figma.com/...` 或 `docs/prototype-order.md` |

## 澄清后的衔接

共识清单会给出推荐的后续分支与模板编号（如「业务文档方案 → fw-dev-spec，用模板 04」）——确认后直接使用对应模板（01~10）进入执行；无需重复已澄清的决策，执行类模板收到的共识清单可直接作为意图清单输入。

## 多 Agent 模式（可选）

本模板默认单 agent 执行（澄清本身无需分工）。若任务确定走多 agent 端到端流程，可在提示词开头追加「用多 agent / 团队协作模式」——编排器 `workflow-orchestrator`（`.agents/workflow-orchestrator.md`）会在其意图解读阶段（对应 SKILL.md 2.1）按同一协议执行 frontier 轮次，澄清结论直接进入工作流初始化（`create-fw-workflow.cjs`）。协议细节见 `references/multi-agent-orchestration.md` §9.5（待确认项管理，grilling 语义）。
