# 提示词模板 06：测试能力（当前为占位，待扩展）

> 规则依据：`references/testing.md`（目前为骨架占位，规则未定稿）。
> 适用：触发测试分支（单元 / 组件 / E2E / 视觉回归）。**注意：本分支尚未定稿，需先补充规范再执行。**

---

## 模板 A：完整版（含“待扩展”提示）

```text
请使用 frontend-workflow skill 的测试分支（references/testing.md）。

【重要前提】
testing.md 当前为骨架占位、规则未定稿。请先 Read 该文件，并向我明确说明“测试规则待扩展”，
**不要凭空套用通用测试模板**。待我补充具体规范（单元 / 组件 / E2E / 视觉回归的写法与 QA Checklist）后再执行。

【输入】
- 测试范围：{{test_scope}}        # 单元 / 组件 / E2E / 视觉回归
- 目标：{{target_path}}           # 待测文件 / 页面 / 模块
- 可映射来源：prototype-to-openspec-prd.md 的 tasks.md 中 Requirement/Scenario → 可执行用例

【执行要求】
1. 先确认 testing.md 是否已定稿；未定稿则停下来，列出需要我补充的规范项。
2. 若我已提供规范，按规范编写并过对应 QA Checklist。
3. 与上下游衔接：E2E 用例可映射 PRD 的 Requirement/Scenario；视觉回归与 figma-design-constraint 的还原验收互补。
```

## 模板 B：精简版（一行触发）

```text
用 frontend-workflow skill 的测试分支（testing.md）给 {{target_path}} 写 {{test_scope}} 测试。注意 testing.md 还是占位，先读文件确认规则是否已定稿，未定稿先告诉我缺哪些规范，别直接套通用模板。
```

## 占位符说明

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{test_scope}}` | 测试类型 | `E2E` / `组件测试` / `单元测试` |
| `{{target_path}}` | 待测目标 | `src/views/order/list.vue` |

> ⚠️ 补全建议：正式使用前，请完善 `references/testing.md` 各测试类型的写法规范、示例代码与 QA Checklist，本模板即可直接驱动执行。

## 多 Agent 模式（占位，规范未定稿）

本模板对应的 `test-engineer`（`.agents/test-engineer.md`）角色已定义，但 `testing.md` 仍为占位骨架——多 agent 模式下同样会触发「测试规范未定稿，需先补充」提示，不会自动套用通用模板。在提示词开头追加「用多 agent / 团队协作模式」后，编排器 `workflow-orchestrator`（`.agents/workflow-orchestrator.md`）会 spawn `test-engineer` 执行；但因规范未定稿，仍须先补全 `references/testing.md` 方可生成测试。完整协议见 `references/multi-agent-orchestration.md`（§十一 3.5 测试）。
