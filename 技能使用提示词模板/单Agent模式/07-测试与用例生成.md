# 提示词模板 07：测试与测试用例生成

> 规则依据：`references/testing.md`（3.5 正式规则）+ `references/cross-cutting.md`（完成前验证铁律 · 三 / 敏感操作 · 四）。
> 适用：触发测试分支（单元 / 组件 / E2E / 视觉回归 / 生成测试用例），或在工作流 ⑨→⑩ 之间插入测试环节。

---

## 模板 A：完整版

```text
请使用 frontend-workflow skill 的测试分支（references/testing.md），为下述目标执行测试能力。

【输入】
- 测试范围：{{test_scope}}        # 单元 / 组件 / E2E / 视觉回归 / 全部
- 目标：{{target_path}}           # 待测文件 / 页面 / 模块
- 业务文档：{{biz_doc_path}}      # 可选：OpenSpec specs / fw_dev_spec 活文档路径；无则由我指定测试范围
- 技术栈：{{tech_stack}}          # 可选；未提供则先探测项目 package.json 既有测试栈

【执行要求（两段式，顺序不可乱）】
1. 先 Read references/testing.md，按第二章生成 Markdown 测试用例文档：
   - 逐条映射 Requirement / Scenario（GIVEN/WHEN/THEN → 前置/步骤/预期），补边界与异常用例
   - 每条用例标注优先级（P0/P1/P2）与回溯锚点，附覆盖矩阵
   - 落位：fw_dev_spec 项目放 fw_dev_spec/<需求>/specs/测试用例.md；OpenSpec 项目放 openspec/changes/<change-id>/测试用例.md；均无则放 test-cases/
2. 【人工 Gate · 用例审阅】用例文档产出后暂停，向我展示用例统计与覆盖情况，等我确认 [通过/调整/返工]。
3. Gate 通过后才生成可执行测试代码：单元/组件按 testing.md 三/四章（跟随项目既有测试栈与命名惯例）；E2E 按第五章（scripts/testing/with_server.py 先 --help，脚本黑盒使用；动态应用先等 networkidle 再侦察 DOM）。
4. 执行测试命令（npm test / playwright / npm install 等）前必须先向我确认（敏感操作，cross-cutting.md 四）。
5. 执行后回写用例文档状态（✅/❌/⏭）；❌ 逐条定位"代码缺陷 vs 用例错误"；未持有本次命令输出证据不得宣称"测试通过"（完成前验证铁律，cross-cutting.md 三）。
6. 回归用例须完成 Red-Green 验证；跳过的用例显式标 ⏭ 及原因；覆盖缺口须声明。
```

## 模板 B：精简版（一行触发）

```text
用 frontend-workflow skill 的测试分支（testing.md）给 {{target_path}} 做 {{test_scope}}：先生成测试用例文档（含覆盖矩阵）交我审阅，Gate 通过后再生成可执行测试并运行；结论须附执行证据，测试命令先问我。
```

## 占位符说明

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{test_scope}}` | 测试类型 | `E2E` / `组件测试` / `单元测试` / `生成测试用例` |
| `{{target_path}}` | 待测目标 | `src/views/order/list.vue` |
| `{{biz_doc_path}}` | 业务文档路径（可选） | `openspec/changes/add-export/specs/` |
| `{{tech_stack}}` | 技术栈（可选） | `Vue3 + TS + Vitest` |

## 多 Agent 模式（可选）

本模板对应角色为 `test-engineer`（`.agents/test-engineer.md`）。在提示词开头追加「用多 agent / 团队协作模式」，编排器 `workflow-orchestrator`（`.agents/workflow-orchestrator.md`）即 spawn `test-engineer` 执行两段式流程；用例审阅为角色内嵌人工 Gate（不占状态机 phase），完整协议见 `references/multi-agent-orchestration.md`（§十一 3.5）。也可直接使用独立模板 `../多Agent模式/07-测试与用例生成-多Agent.md`。
