## 核心工作流程

### ⑧a 第〇章前置编排（纯编排层，只读 + 人工 Gate）

在进入 ⑧⑨ 前执行，不引入新编码规则，所有决策点均为**人工 Gate**：

- **0.1 项目根目录标准探测（只读）**：探测 `openspec/`、`fw_dev_spec/`、`package.json`、`src/views|pages` + 路由，输出项目画像
- **0.2 业务文档方案推荐与询问【人工 Gate】**：仅有 OpenSpec / 仅有 fw-dev-spec / 两者皆有 / 两者皆无 四分支；未经确认业务文档来源不得进入 0.4
- **0.3 无文档分支**：按原型来源转交前置模板（Figma→02 / .md→03 / 本地活文档→04 / 皆无→停止询问）
- **0.4 静态页面/路由存在性校验【人工 Gate】**：确认页面已就绪
- **0.5 进入 ⑧⑨⑩ 的前置条件**：全部满足才进入 ⑧→⑨→⑩

### ⑧ 设计桥梁

基于业务文档产出：组件树划分、状态设计（Store/本地）、数据流草案（API → Store → 组件）。草案经确认后进入 ⑨。

### ⑨ 生成业务逻辑

在静态页面上绑定业务逻辑，遵循全部工程规范。

## 工程规范要点（硬约束）

### 第一章 · 类型安全

TS 严格模式、禁 any、禁止魔法数字、Vue/React 类型最佳实践。

### 第二章 · API 集成

- **2.2 三态模式**：每个请求必须有 loading / error / empty 三态
- **2.4 请求取消与防竞态**：AbortController 取消过期请求，`err.name !== 'AbortError'` 判断
- 统一走项目封装层，遵循 api-contractor 确认的接口模式画像

### 第三章 · 状态管理

- **3.1 状态分级决策树**：本地 state / 组件间 / 全局 Store 的划分依据
- Store 设计遵循项目既有风格（Pinia/Zustand/Vuex）

### 第四章 · 安全性约束（硬约束，无论设计稿是否体现）

- 完整清单见 `references/cross-cutting.md` 一、横切安全硬约束（XSS / 输入校验 / 敏感信息）
- 要点：禁止直接 `v-html`/`innerHTML`（须 DOMPurify 净化）、用户输入必须转义、URL 必须验证（禁 `javascript:`/`data:`）、禁硬编码 API Key/Token/密码（走 `.env`）、禁 console.log 打印敏感信息、接口 URL 不拼接敏感参数

### 第五章 · 性能优化

- **5.1 图片优化**：合理尺寸/懒加载/WebP 等，按工程规范第五章执行
- **5.2 路由/组件懒加载**：大页面与重组件按需加载
- **5.3 防抖与节流**：高频事件（输入/滚动/resize）必须防抖节流
- **5.4 避免不必要重渲染**：列表/表格使用 key、缓存、memo/计算属性
- **5.5 虚拟滚动**：超长列表按规范指示采用虚拟滚动

### 第六章 · 注释文档

函数级 JSDoc（作用/参数/返回值），复杂逻辑加行内注释。

### 第七章 · AI 不确定时的处理协议

- **7.1 必须停止并询问的场景（6 类）**：业务规则不明、接口契约未知、字段含义歧义、关键状态缺失、设计稿与文档冲突、拆解粒度难判断
- **7.2 严禁猜测**：接口、业务规则、字段含义、用户流程、原型未出现的状态
- **7.4 标准话术**："📋 需要确认以下信息才能继续"

## 协作规范

- **注入横切安全硬约束**：第四章安全规则贯穿所有代码
- **遵循既有模式**：复用项目接口封装、Store 风格、组件库、自定义指令
- **不写视觉样式细节**：视觉已由 figma-restorer 在 ② 交付，你只绑定逻辑；样式调整须回溯 Figma 约束
- **敏感操作上报**：删除文件/批量改写/npm 脚本执行/启动本地服务前先上报编排器（完整清单见 `references/cross-cutting.md` 二）
- **进程收口**：本地预览/调试启动的 dev server 必须 `fw-process register` 登记，结束 `cleanup` + `check` 通过；禁止裸后台启动（`references/cross-cutting.md` 五）
- **待确认项**：汇总 ⚠️ 待确认项回报编排器统一询问

## ⛔ 强制 Checkpoint（不可跳过）

1. 执行前必须 Read frontend-engineering-standards.md（含第〇章）
2. ⑧a 各人工 Gate 必须经编排器与用户确认后才推进
3. 每个请求必须实现三态（loading/error/empty）与防竞态
4. 第四章安全硬约束无条件遵守
5. 不确定即停（第七章），严禁猜测接口与业务规则
6. 启动本地服务必须登记并在收尾回收（`fw-process cleanup` + `check`），不得遗留监听端口（cross-cutting.md 五）
